# GitPR 1.1.0 — What's New

## What's New in This Version

- **`gitpr config` — the interactive configuration TUI:** A master-detail screen over `~/.gitpr/.env` with a category sidebar, inline field editing, global search (`/`), `F2` to save, `Ctrl+R` to restore and `Esc` to discard. A declarative schema (`src/config_schema.py` — 12 categories, 56 `ConfigField`, 8 advanced) is the single source of truth: menu, widgets, defaults and validation all derive from it, so adding a setting is now a change of data, not of interface.
- **A Skills section inside the TUI:** The first project-scoped surface of the screen edits your project's `.gitpr/skill/*.md` files atomically (preserving CRLF/LF) in the same `F2` pass that writes the `.env`, with one shared pending-changes counter.
- **General usage log:** One line per command in `~/.gitpr/logs/<date>.log` — one file per day, written synchronously, never printing and never raising. It answers "what did I actually run, and when?". Controlled by `GITPR_SHOW_LOGS`.
- **Git hooks language fix:** The language you chose is now really honored — `HOOK_SCRIPT_SUFFIXES` maps interface codes (`es_es`, `fr_fr`) to the published suffixes (`.es`, `.fr`), and `--lang` is no longer ignored.
- **PyPI-only distribution with a mandatory update gate:** The binary channel is gone — no generation, no upload, no fallback. `enforce_update_required()` blocks execution with exit code 1 when a newer version is published and prints the exact command to run.
- **i18n expanded to 955 keys:** +213 keys covering the configuration TUI and the PyPI gate, with full key-set parity across all 6 dictionaries (`__lang_version__` v0.0.25).
- **2 new documentation families in 5 languages:** `config-tui` and `usage-log`, plus 7 updated topics (`ARCHITECTURE`, `auto-update`, `hooks-versioning`, `mcp-integration`, `skill-template`, `testar_sem_usar_pypi`, `version-markers`).
- **Dead key removed:** `PR_AUTO_PUBLISH` was proven unused and taken out — if an older install still carries the line, it now simply shows as read-only under *Unknown*.
- **Version 1.1.0:** `__version__` moved from 1.0.0 to 1.1.0, and `CHANGELOG.md` records `[1.1.0] - 2026-09-13`, generated by `gitpr release` itself.

## How to Use

GitPR 1.1.0 ships exclusively through PyPI — the standalone binary channel has been retired:

```
pip install --upgrade gitpr-cli
```

Heads-up: from this version on, GitPR checks PyPI on every run and **blocks execution** if a newer version is published, telling you exactly what to run. The check is cached per day, `--update` only reports, and `GITPR_SKIP_UPDATE_CHECK` turns the gate off for offline automation.

Configure everything from the new TUI — no need to hand-edit `~/.gitpr/.env`:

```
gitpr config            # interactive configuration screen (F2 saves)
```

Editing your project's AI instructions happens on that same screen: the Skills section writes `.gitpr/skill/*.md` in the same save pass.

Want to know what you actually ran, and when? Every command is appended to a daily log:

```
~/.gitpr/logs/<date>.log    # one file per day; turn it off with GITPR_SHOW_LOGS=false
```

Language fixes landed too: `--lang` now also applies to your Git hooks, so the hook scripts follow the language you actually chose.

## Useful Tips

Mixed-language team? `gitpr --lang <code>` overrides the language for a single run: `gitpr -c --lang en`, `gitpr -r --lang pt_br`, `gitpr -ch --lang fr`. GitPR speaks 5 languages and auto-detects your system locale on first run — and since 1.1.0 that choice also reaches your Git hooks.
