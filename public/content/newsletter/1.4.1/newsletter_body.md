# GitPR 1.4.1 — What's New

## What's New in This Version

- **`gitpr check` — a single gate for CI:** linter, secrets scan, SAST bridges, risk score, baseline and optional AI review now run behind **one command**, with **SARIF 2.1.0**, **JSON** or **JUnit XML** artifacts and a deterministic output contract (`0` success, `1` blocking finding, `2` execution error). `action.yml` was rewritten to call this command, the API key is no longer mandatory and there is a zero-cost `--no-ia` path.
- **VS Code and Cursor extension — the editor became an MCP client:** eight commands (`commit`, `review`, `fullReview`, `reviewMentor`, `generatePr`, `generatePrExplain`, `publishPr`, `check`) talk to `gitpr-mcp` over stdio and **never duplicate business logic** — keys, tokens and prompts stay on the CLI side. The extension publishes PRs in two steps, populates the **Problems** panel with the findings from `run_check` and masks secrets on both sides of the boundary.
- **Two new MCP tools and a shared use case:** `run_check` (read-only, `no_ia=true` by default) and `publish_pull_request` (never commits and never pushes) entered the server, which went from **16 to 18 tools**. The `--no-edit` publication no longer has its own code: CLI and MCP go through the same `publish_pull_request_use_case`, with the statuses `success`/`needs_push`/`already_exists`/`auth_required`/`error`.
- **The PR skill stopped propagating an accidentally pasted artifact:** a JSON fragment (`".gitpr.commit.md": "gitpr.commit.md",`) ended up in the structure rule of the `pt_br` template and the AI echoed it in **every** generated PR. Since `--skill` never overwrites an existing file, fixing the template was not enough: `get_skill_context()` now **removes the fragment in memory** (without touching the user's file), and a new test scans **every published template** to prevent recurrence.
- **PR merge gained visual feedback:** the forge call ran silently on a daemon thread and an unexpected exception **killed the thread without warning**, leaving the TUI stuck. The existing progress modal was generalized (`title` optional, `mark_finished(show_close=False)`), started being pushed before the worker begins and now covers **success, conflict and unexpected error**, with auto-dismiss after 1.2 s on the happy path.
- **The i18n debt reopened — and the suite reports it:** **8 `__()` keys used in the code do not exist in any dictionary** (PR publication and MCP tool descriptions) and **2 became orphans**; `es.json` and `fr.json` stayed at **1618** keys against 1620 in the other four. Added to the **7 failures in `tests/badge/test_badge_paths.py`** — the tests' fake provider has no `.token`, and the shared use case now requires one — and to the **2 known failures** in `tests/test_mentor_cli.py`, the suite closes at **2938 passed out of 2952** (12 failures, 2 skips).
- **Release 1.4.1 is prepared, but not yet closed:** `__version__` went up to **1.4.1** (commit `46c25c1`) and `__lang_version__` to **v0.0.35**; `CHANGELOG.md` already has the `[1.4.1]` section generated by the release engine — **in the working tree**, and the `v1.4.1` tag still **does not exist**.

## How to Use

Upgrade from PyPI:

```
pip install --upgrade gitpr-cli
```

The release is built around a single CI command:

```
gitpr check                                      # linter, secrets, SAST, risk and baseline — plus optional AI review
gitpr check --format sarif --output gitpr.sarif  # SARIF 2.1.0 artifact for GitHub Code Scanning
gitpr check --no-ia                              # zero-cost path: no AI call and no API key required
gitpr check --fail-on warning                    # make warning-level findings block the build
```

The exit code is the contract: `0` success, `1` blocking finding, `2` execution error. The artifact can also be emitted as `json` or `junit`.

For VS Code and Cursor, install the `natanfiuza.gitpr` extension from the Marketplace (or Open VSX) and run the commands from the Command Palette: Commit, Review, Full Review, Review with Mentor, Generate PR, Generate PR with Reviewer Guide, Publish PR and Check. `GitPR: Check` fills the Problems panel with clickable diagnostics; keys and tokens stay in `~/.gitpr/.env`.

## Useful Tips

Diffs bigger than ~90k tokens (estimated at 4 characters per token) are handled automatically: GitPR splits them into batches at file boundaries, summarizes each part (Map) and unifies everything in a final call (Reduce) — no flags needed.
