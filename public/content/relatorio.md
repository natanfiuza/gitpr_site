# **🚀 Project Status Report: GitPR CLI — v0.0.18 (2026-10-18)**

## **📌 Overview**

**GitPR** is an advanced CLI (Command Line Interface) tool for automating Git processes using Artificial Intelligence (Google Gemini / DeepSeek / Ollama). Its main goal is to act as a local intelligent assistant that performs Code Reviews, generates Pull Requests, semantic commit messages, audits technical debt, and injects best practices into the developer workflow (Shift Left).

**What's New in This Version (v0.0.18):**
- **`gitpr check` — a single gate for CI:** linter, secrets scan, SAST bridges, risk score, baseline and optional AI review now run behind **one command**, with **SARIF 2.1.0**, **JSON** or **JUnit XML** artifacts and a deterministic output contract (`0` success, `1` blocking finding, `2` execution error). `action.yml` was rewritten to call this command, the API key is no longer mandatory and there is a zero-cost `--no-ia` path.
- **VS Code and Cursor extension — the editor became an MCP client:** eight commands (`commit`, `review`, `fullReview`, `reviewMentor`, `generatePr`, `generatePrExplain`, `publishPr`, `check`) talk to `gitpr-mcp` over stdio and **never duplicate business logic** — keys, tokens and prompts stay on the CLI side. The extension publishes PRs in two steps, populates the **Problems** panel with the findings from `run_check` and masks secrets on both sides of the boundary.
- **Two new MCP tools and a shared use case:** `run_check` (read-only, `no_ia=true` by default) and `publish_pull_request` (never commits and never pushes) entered the server, which went from **16 to 18 tools**. The `--no-edit` publication no longer has its own code: CLI and MCP go through the same `publish_pull_request_use_case`, with the statuses `success`/`needs_push`/`already_exists`/`auth_required`/`error`.
- **The PR skill stopped propagating an accidentally pasted artifact:** a JSON fragment (`".gitpr.commit.md": "gitpr.commit.md",`) ended up in the structure rule of the `pt_br` template and the AI echoed it in **every** generated PR. Since `--skill` never overwrites an existing file, fixing the template was not enough: `get_skill_context()` now **removes the fragment in memory** (without touching the user's file), and a new test scans **every published template** to prevent recurrence.
- **PR merge gained visual feedback:** the forge call ran silently on a daemon thread and an unexpected exception **killed the thread without warning**, leaving the TUI stuck. The existing progress modal was generalized (`title` optional, `mark_finished(show_close=False)`), started being pushed before the worker begins and now covers **success, conflict and unexpected error**, with auto-dismiss after 1.2 s on the happy path.
- **The i18n debt reopened — and the suite reports it:** **8 `__()` keys used in the code do not exist in any dictionary** (PR publication and MCP tool descriptions) and **2 became orphans**; `es.json` and `fr.json` stayed at **1618** keys against 1620 in the other four. Added to the **7 failures in `tests/badge/test_badge_paths.py`** — the tests' fake provider has no `.token`, and the shared use case now requires one — and to the **2 known failures** in `tests/test_mentor_cli.py`, the suite closes at **2938 passed out of 2952** (12 failures, 2 skips).
- **Release 1.4.1 is prepared, but not yet closed:** `__version__` went up to **1.4.1** (commit `46c25c1`) and `__lang_version__` to **v0.0.35**; `CHANGELOG.md` already has the `[1.4.1]` section generated by the release engine — **in the working tree**, and the `v1.4.1` tag still **does not exist**.

## **🧩 Implemented Modules and File Architecture**

### **1. Core and Git Operations (`src/core.py`)**

* **Structured Generation:** Communicates with the LLM requesting a strictly JSON response.
* **Map-Reduce (Giant Diffs):** When the diff exceeds ~90k tokens, it automatically splits into per-file batches (`split_diff_into_chunks`), processes each part (Map) and unifies the summaries (Reduce). Supports PRs, commits and Issues. `provider`/`model` are aggregated across the chunks and `meta`/`modules` are passed on to `log_command_metric`, which copies real tokens from the provider metadata at write time.
* **Local Tokenizer:** `tokenizer.json` for precise token estimation before sending to the AI.
* **Token Estimation:** Lightweight heuristic `len() // 4` via `estimate_token_count()` with a fallback to the local tokenizer.
* **Native Git Optimization:** `-U1`, `-w`, `-M`, `-B` flags on the `get_git_diff` and `get_git_full_diff` commands to reduce useless context.
* **`get_split_diff()`:** `split`'s own diff, with `SPLIT_DIFF_ARGS` (`--binary -M -U3`), **deliberately without** reusing `get_git_diff()` — `-w` (ignore whitespace) and the smart-excludes would break the byte-identical tree guarantee.
* **Pre-Save (`--pre-save`):** Hidden debug flag that saves the full payload (system instruction + prompt) as JSON before every AI call.
* **Two-Layer Smart Excludes:** Global layer (`~/.gitpr/conf/`) + project-local (`./.gitpr/conf/`), merged at runtime. Auto-seeding of the local file on first run. `_load_smart_excludes()` accepts `force=`.
* **Metrics with Time Tracking:** `log_command_metric()` in every flow, now with `meta`, `modules` and `duration_ms`.
* **Centralized Output Resolution:** `resolve_output_path()` — defaults to `.gitpr/reports/{type}/`.
* **SCM Wizard (`run_scm_init_wizard()`)**: `gitpr --init` — detects the forge from the origin remote, requests per-forge extras, validates the token and persists **only on success**; announces the automatic badge on the PR path.
* **Release Skill Template (`ensure_release_skill_template()`)**: Downloads `templates/gitpr.release.*.md` on the first use of `gitpr release`.
* **Corrupted Skill Guard 🆕:** `_CORRUPTED_PR_SKILL_ARTIFACT` documents the JSON fragment that leaked into the `pt_br` template, and `get_skill_context()` removes it **in memory** when `action_type == "pr"` — the user's file remains byte-for-byte intact, and the other actions (`commit`, `review` etc.) read the file verbatim. Since the prompt changes, the cache MD5 key also changes and contaminated responses are no longer reused.
* **Shared Skill Registry:** `SKILL_FILES_BY_TYPE` / `SKILL_TYPES` / `DEFAULT_SKILL_TYPE` in `src/config.py`, with the `mentor` entry already registered.
* **Review Engine with Cache Scope (`generate_pr_content`):** `cache_scope` (attached **only to the cache key**) and `store_diff` (writes the reviewed diff); `cache_scope` also carries the active policy pack.
* **Co-authorship Trailer:** `COAUTHOR_TRAILER` + `append_coauthor_trailer()` — idempotent, preserves third-party trailers.
* **Hardened Subprocesses:** `stdin=subprocess.DEVNULL` + `encoding='utf-8'`/`errors='replace'` on every `subprocess.run`; connection check via the `8.8.8.53:53` socket before network operations.

### **2. Global Plugin System (`src/plugins.py`)**

* **Plugin Architecture:** Loads plugins from `~/.gitpr/plugins/` applying to **all projects**.
* **Linter Plugins (`linter/`):** `.yml` files merged with the local `.gitpr.linter.yml`.
* **MCP Prompt Plugins (`prompts/`):** `.md` files that extend the system context.
* **Factory Closures:** `get_linter_plugins` and `get_prompt_plugins` isolate state between sessions.
* **`--plugins` Command:** Lists all installed global plugins with types and paths.
* **Multilingual Documentation:** `docs/plugins-system.md` in 5 languages.
* **Relationship with Policy Packs:** the pack is a **third** layer of rules — plugins belong to the machine, `.gitpr.linter.yml` belongs to the project and the pack is versioned and committed. `load_linter_rules()` merges the three in declared order, with the pack's severities on top.

### **6. Static Analysis Engine / Linter (`src/linter_engine.py`)**

* **Offline Linter:** Statically analyzes the added (`+`) lines in the diff without spending AI quotas.
* **YAML Rules:** Reads `.gitpr.linter.yml` (created via `--skill`).
* **Linter Plugins:** Additional rules from `~/.gitpr/plugins/linter/*.yml`.
* **Extension Wildcard:** `extensions: ["*"]` means **every** file, including those without a suffix and dotfiles.
* **Built-in Secrets Ruleset:** `load_linter_rules()` merges `src/security_ruleset.py` **after** the project rules and the plugins. Seven rules, all `extensions: ["*"]`: five `error` and two `warning`. The alert **never echoes the value**.
* **Policy Pack Layer:** `load_linter_rules()` applies the layered merge of the active pack and **overrides severities**, without touching `.gitpr.linter.yml` or the plugins.
* **Structured Findings (`findings_out`):** besides the alert strings, the engine returns the normalized findings of the canonical type `src/domain/finding/` — that list is what the baseline fingerprints and what `gitpr check` serializes.
* **Opt-In SAST Bridges:** Semgrep, Gitleaks and Bandit run on the whole-file path **and** on the diff path, with `[Gitleaks + Regex]` dedup, value masking (`AKIA****`) and a warning when the tool is enabled but not on `PATH`.
* **`skip_external`:** `parse_diff_and_lint(..., skip_external=True)` in the remote flow, because the bridge runs binaries against files on disk — the local tree, not the PR.
* **Consolidated Report:** `generate_linter_report_content()` consolidates regex + external errors into `.gitpr/reports/linter/` — generated only when there are violations.
* **Baseline-aware:** the alerts are annotated with the baseline status before becoming a report, and the lint flow's exit code follows the baseline-aware blocking.

### **7. Security and Authentication (`src/security.py`, `src/config.py`, `src/tui_issue.py`)**

* **Cryptography:** Generates the `secret.key` master key in `~/.gitpr/`.
* **Token Protection:** `encrypt_data`/`decrypt_data` for AI keys, GitHub PAT and SCM tokens for the forges.
* **Multi-Forge Validation:** `validate_or_request_scm_token(provider, repo_display)` — 401 → reauthentication loop preserving the draft.
* **Secrets in the Configuration TUI:** `KIND_SECRET` fields are edited masked, **never** display the value in the clear and are encrypted with Fernet before writing.
* **Secrets Scanning in the Flow:** The linter — which runs in the pre-commit hook — is a credential gate with identical rules on every machine.
* **Masking in CI 🆕:** `src/infrastructure/ci/masking.py` removes private keys, AWS access key ID/secret, GitHub tokens (`gh[pousr]_`, `github_pat_`), Google (`AIza`), OpenAI (`sk-`), Slack (`xox[baprs]-`), `Bearer`, basic-auth in URL and generic password assignments **before** the artifact is serialized. The same module is used by `publish_pull_request_use_case` to avoid leaking a token in error messages, and the extension has a mirror in TypeScript (`masking.ts`).
* ⚠️ **Coverage gaps confirmed as still open:** the generic rule still requires quotes after the separator (`\s*[:=]\s*['\"]`), so the `.env` format **without quotes** (`API_KEY=abc123`) is still not caught; the `ASIA…`, `github_pat_…` and `xoxc-`/`xoxd-` prefixes are still out of the **linter's** ruleset (the CI masking already covers `github_pat_`, but not `ASIA…` nor `xoxc-`/`xoxd-`); and there is no left boundary on the key name, so `mytoken` matches the same as `token`.

### **22. `gitpr release` Subcommand — Changelog / Release Notes (`src/release_engine.py`)**

* **Flow:** `git log` between `--since` and `HEAD` → classification by Conventional Commits → suggested semantic bump (`--version <x.y.z>` overrides) → changelog assembly → optional AI executive summary → *prepend* to `CHANGELOG.md`.

* **`_drop_released()` — the second line of defense:** any commit whose short hash appears in **another** version section is discarded, with a count. When nothing survives, the run **aborts** with `❌ Nothing new to release`.
* **Every bullet became a link:** `- {subject} ([{short_hash}]({commit_url})) — {scope} · [#{n}]({pr_url}) · {YYYY-MM-DD}`.
* **The merged-PR-by-merge-commit failure:** a second pass (`git log --merges`) builds `hash → PR` from ancestry; a merge that is not a pull request does not borrow a number, and the correction **is not retroactive**.
* **Contributors resolved by the same reviewer ladder:** `get_commit_author_login` first, then `email_to_handle`, cached in `~/.gitpr/cache/contributors.json`.
* **The Section Boundary Was a Latent Bug:** `upsert_changelog(force=True)` replaces from the `## [x.y.z]` line to the next **level-2** header; a `###` as the boundary left the old body alive above the new one.
* **Classifier (`src/commit_classifier.py`)** and **Builder with Translatable Sections (`src/changelog_builder.py`)** — the builder has the `LinkContext` dataclass, and the classifier has `pr_number_from_merge()`.
* **Semantic Bump (`src/version_bump.py`)** and **Publication** (`--publish`, `--draft`, `--format markdown|json`, `--force`). **6 options on the subcommand.**
* **Declared breaks:** `ReleaseNotesResult` gained `previous_version`; `build_release_section` gained `links` (backward compatible).

### **36. SQLite Telemetry Ledger (`src/ledger.py`, `src/infrastructure/git/identity.py`)**

* **The Problem Was Not the Format, It Was the Join:** events were written as JSON files per command, from a **daemon thread**, and later reconnected to the AI cache by a heuristic `(repo, branch, action, minute)` match that depended on **three divergent command→folder maps**.
* **The Write is Synchronous, and That is the Decision:** `log_command_metric()` resolves the git context **once per process** and writes the row on the spot. Tokens, model and provider are **copied from the provider metadata at write time**.
* **Versioned Schema:** `SCHEMA_VERSION` + `PRAGMA user_version`, UUID keys, WAL + `synchronous=FULL`, and `LedgerVersionError` to refuse a newer bundle **before** `ATTACH`.
* **The "Never Born Empty" Invariant:** `ensure_ledger()` only creates the database **together with** the absorption of the legacy JSON (originals moved to `~/.gitpr/metrics_legacy/`).
* **One Window, One Meaning:** `--since`/`--until`/`--days` narrow **every** read surface; the cycle section assumes the last 30 days and **names the window in its own header**.
* **Each Metric is Computed Once and Rendered Once:** the `(style, text)` pairs make the CLI and the Textual dashboard tell the **same** story.
* **Cost with Embedded Table and Override:** list prices for the four models, overridden by `GITPR_METRICS_PRICE_<MODEL>_INPUT`/`_OUTPUT`. **Both rates are mandatory**; `ollama`/`local` cost zero; a non-USD `GITPR_METRICS_CURRENCY` **discards** the embedded table; a partial total reads `Total (partial)`.
* **Normalized `modules`:** paths become two segments (`src/fix`), `(root)` and `(no module)` for commands without a diff.
* **Bundle Transport:** `bundle` writes the window as a standalone `.db`; `merge` attaches it, inserts by UUID, migrates an old bundle and refuses a newer one.
* **`cache_backfill` is Left Out:** rows rebuilt from the cache are excluded from the execution aggregates.
* **Git Identity without a Forge (`identity.py`):** repo, branch and author label in a **single** subprocess call, valid on any forge.
* **The Cycle Section is the Only One the Ledger Cannot Answer:** it lists merged PRs via `ScmProvider.list_pull_requests`; every failure degrades to one line — `Not read: <reason>` — never a stack trace.
* **Complete Presentation:** `gitpr metrics` group with 8 subcommands, a dashboard reading the ledger on a worker thread and the three-option migration assistant.
* **Configuration:** `GITPR_METRICS_PRICE_<MODEL>_INPUT`/`_OUTPUT`, `GITPR_METRICS_CURRENCY` and `.gitpr/metrics/` in `.gitignore`.
* **Tests:** `tests/test_metrics.py` (**164 scenarios**); `tests/scm/*` covers pagination and `within_window`; `test_commit_classifier.py` (30) covers `pr_number_from_merge`.
* **Artifacts:** ADR-008, `glossary-metrics-telemetry.md`, `docs/plans/develop_natan/20260927_metrics_audit_plansfacts.md`, survey and `docs/metricas-telemetria.*.md` in the 5 languages.

### **38. `gitpr risk` Subcommand — Deterministic Risk Score (`src/domain/risk/`)**

* **What it is:** A **0–100** score with level `LOW`/`MEDIUM`/`HIGH`/`CRITICAL`, calculated **without AI** from local signals, so the reviewer knows where to look first — and so the same diff receives the same number twice.
* **Pure Domain Layer (`risk_types.py`, `risk_rules.py`, `risk_calculator.py`, `risk_explanation.py`):** enums and dataclasses (`RiskLevel`, `RiskSignal`, `RiskEvidence`, `FileRisk`, `PullRequestRisk`); weights, thresholds, critical-path patterns, glob matching and test/non-executable detection loaded from YAML; per-file calculation with **clamp 0–100** and 50/30/20 aggregation.
* **The Formula is Declared, Not Learned:** **50%** the highest-risk file, **30%** the line-weighted average and **20%** critical evidence. Mandatory elevation rules: score ≥ 80 rises to at least `HIGH`; a blocker or score ≥ 90 forces `CRITICAL`.
* **Infrastructure Adapters:** `risk_history_reader.py` reads `git log` and extracts commits, bug fixes and reverts over a **90-day** window; `test_matcher.py` matches test ↔ production files by convention.
* **Use Case (`calculate_risk.py`):** correlates diff sections, findings, test matching and history into `FileRisk`/`PullRequestRisk`, **degrading with a warning** when a signal is unavailable. Applies the policy pack on top of the base configuration.
* **Three Consumers:** the `gitpr risk` command, the `⚡ Risk Assessment` section appended to reviews and to remote PR review, and the **AI prompt** as **read-only** context. 🆕 `gitpr check` uses the same `execute_calculate_risk` for the preliminary and aggregate score.
* **Opt-Out:** `GITPR_RISK_INCLUDE_IN_REVIEW` (default `true`).
* **Per-Project Configuration:** `templates/gitpr.risk.yml` (or `.gitpr/skill/gitpr.risk.yml`) overrides weights, thresholds and critical paths. Negative weights are only accepted for **mitigating** signals.
* **Tests:** `tests/domain/risk/` (2 files, 10), `tests/application/use_cases/test_calculate_risk.py` (5), `tests/infrastructure/git/test_risk_history_reader.py` (4), `tests/infrastructure/git/test_test_matcher.py` (5) and `tests/test_risk_cli.py` (4).
* **Artifacts:** `docs/risk-scoring.*.md` in **5 languages**, ADR-010, `glossary-gitpr-risk-scoring.md` and task reports.

### **40. `gitpr baseline` Subcommand — Baseline and Auditable Suppressions (`src/domain/baseline/`)**

* **What it is:** Linters and reviews re-report the same pre-existing findings on every run. The baseline records the **snapshot of the findings the repository already knows about** in `.gitpr/baseline.json`, fingerprints each one stably across runs and lets the pipeline classify what is new — **only `new` blocks**.
* **Domain Layer (`baseline_fingerprint.py`, `baseline_types.py`, `baseline_manifest.py`, `baseline_comparator.py`, `suppression_policy.py`):**
  * **Stable fingerprint:** rule identity, normalized path, lines and **sha256 of the line with collapsed whitespace** — the raw line is **never** stored, so the baseline is not a file where secrets leak by accident.
  * **Canonical manifest:** canonical JSON with checksum, validation that refuses an unknown key, an unsupported schema/fingerprint version, a broken suppression/debt invariant, a duplicate fingerprint and an invalid line range.
  * **Comparator:** classification, counts by status and entry resolution — `resolved` and then `back` reads as **new**, the conservative reading.
  * **Suppression Policy:** suppressions, accepted debt, overrides and validators, with layered matching (entry × overrides × policy pack) by **specificity and precedence**, plus overdue-debt tracking.
* **Five Use Cases:** `baseline_gate` (the pipeline's single entry point), `baseline_summary` (read-only JSON view for IDEs and MCP agents), `compare_against_baseline`, `create_baseline` (creation/update with provenance, checksums and **preservation of human decisions**) and `suppress_finding` (four scopes).
* **Policy Pack Integration:** the pack can carry a `baseline:` block, validated by the **same** validators, composed by the resolver as a labeled layer and reported by `policy validate`.
* **Repository is the Only Writer:** `local_baseline_repository.py` is the **only** reader/writer of `.gitpr/baseline.json` and `.gitpr/baseline.overrides.yml`, with atomic writes, checksum/version gate and a repair path.
* **Configuration:** `GITPR_BASELINE_ENABLED`, `GITPR_BASELINE_PATH`, `GITPR_BASELINE_REQUIRE_LOCKFILE_CHECKSUM_MATCH` and `GITPR_BASELINE_ALLOW_LOCAL_OVERRIDES`, in the `baseline` category.
* **Opt-In and No-Op:** disabled or without an existing baseline, the feature **reads no file and prints nothing**.
* **⚠️ The Deliberate Exception:** a baseline file that exists but **cannot be applied** makes lint, review, full review, file audit, remote review and risk **abort with exit code 1**. 🆕 In `gitpr check`, a corrupted baseline exits with **code 2**, distinguishing an execution error from a blocking finding.
* **Reach:** CLI (6 subcommands, all with `--format json`), MCP (`get_baseline_status` + `baseline://summary`), remote PR review (resolved **before the first network call**) and the lint flow.
* **Refactoring the Feature Required:** `NormalizedFinding` became a canonical type in `src/domain/finding/` (with `snippet_hash` and `rule_version`).
* **Tests:** `tests/domain/baseline/` (5 files, **126**), `tests/application/use_cases/` (5 files, **141**), `tests/infrastructure/baseline/test_local_baseline_repository.py` (24), `tests/domain/finding/test_finding_types.py` (3), `tests/domain/linter/test_structured_findings.py` (44), `tests/test_baseline_cli.py` (54) and `tests/integration/test_baseline_effect_on_review_linter_risk.py` (34).
* **Artifacts:** `docs/baseline-suppressions.*.md` in **5 languages**, ADR-012, `glossary-baseline.md`, spec/plan/survey and task report.

### **41. `gitpr check` Subcommand — Unified CI Gate (`src/domain/check/`, `src/infrastructure/ci/`) 🆕**

* **What it is:** A **single entry point** for CI pipelines (GitHub Actions, GitLab CI, Azure Pipelines, Jenkins) that orchestrates static analysis, SAST bridges, secrets scanning, optional AI review, risk score and baseline classification, and emits **one standardized artifact** with a deterministic exit code.
* **The Pipeline Order is Contract:** (1) policy resolution — invalid exits with `2`; (2) diff extraction with smart excludes; (3) regex linter + secrets + external bridges; (4) preliminary risk score; (5) **optional AI review** (`--no-ia` disables it; no configured key degrades with a warning; an in-flight failure exits with `2`); (6) baseline classification (`new`/`existing`/`ignored`/`accepted_debt`/`resolved`; a corrupted baseline exits with `2`); (7) `--fail-on` threshold evaluation; (8) artifact generation with **secrets masking**.
* **Domain Layer (`src/domain/check/`):** `check_types.py` (severity normalized into three levels — `error`/`warning`/`info` — with spec aliases: `minor → warning`, `major|critical|blocker → error`, plus `CheckFinding`, `CheckResult`, `CheckSummary`); `check_config.py` (precedence **CLI > env > defaults**, with `GITPR_CHECK_*`); `check_output.py` (format dispatch and atomic write).
* **Infrastructure Layer (`src/infrastructure/ci/`):** `sarif_builder.py` (SARIF 2.1.0 compatible with GitHub Code Scanning, with `tool.driver.rules` generated dynamically); `junit_builder.py` (testsuites with `<failure>` for blocking findings and `<system-out>` for info/warning); `masking.py` (masking before serializing — private keys, AWS, GitHub, Google, OpenAI, Slack, Bearer, basic-auth and generic assignments).
* **Use Case (`run_check.py`):** `resolve_diff_base()` (explicit → `GITHUB_BASE_REF` → `origin/main` → `HEAD`), execution of the linter and bridges, risk score, optional review, baseline and the final envelope. Stdout emits **only the artifact**; warnings and logs go to stderr.
* **Exit Codes:** `0` success; `1` countable finding at the threshold; `2` execution error (invalid configuration, missing policy, corrupted baseline, in-flight AI failure, 300 s timeout).
* **CLI:** `gitpr check` with 8 options and 9 `GITPR_CHECK_*` variables (outside `DEFAULT_CONFIG`). The command default is SARIF to stdout; `--output` writes a file.
* **Rewritten GitHub Action:** `action.yml` became a single `gitpr check` step, with inputs `provider`, `api-key` (now **optional**), `format`, `output`, `fail-on`, `no-ia`, `baseline` and `policy`. **Declared break:** workflows that depended on the old step (`--linter` + `--fullreview`) and on the `*_PR_FULLREVIEW.txt` artifact need to migrate.
* **Tests:** **37 scenarios** — `tests/application/use_cases/test_run_check.py` (8), `tests/domain/check/test_check_types.py` (8), `tests/domain/check/test_check_config.py` (3), `tests/domain/check/test_check_output.py` (3), `tests/infrastructure/ci/test_masking.py` (6), `tests/infrastructure/ci/test_sarif_builder.py` (2), `tests/infrastructure/ci/test_junit_builder.py` (2) and `tests/test_check_cli.py` (5).
* **MCP:** the `run_check` tool returns the JSON envelope of the same pipeline, with `no_ia` defaulting to `true` to keep the editor check cheap.
* **Artifacts:** `docs/check-ci.*.md` in **5 languages**, ADR-013, `glossary-check-ci.md`, spec, `plansfacts` and survey.

### **42. Editor Extension — VS Code and Cursor (`extensions/vscode/`) 🆕**

## **🔄 Distribution Pipeline**

1. **PyPI (single channel):** `python -m build` → `twine upload dist/*` → `pip install gitpr-cli`
2. **Mandatory update:** execution checks PyPI on startup and **blocks with exit code 1** if there is a newer version, printing `pip install --upgrade gitpr-cli`; the check is cached per day and `--update` only reports
3. **GitHub Releases:** removed — no PyInstaller, no `.exe` asset, no hot-swap
4. **GitHub Actions:** `pr-review.yml` workflow + `action.yml` (installs via pip) + `tests.yml` (Python 3.10 and 3.13 matrix) + **`extension.yml`** 🆕 (VSIX; publishing to Marketplace/Open VSX on `ext-v*`). `action.yml` was rewritten for a single `gitpr check` step — **declared break** for those using `--linter` + `--fullreview`.
5. **MCP Server:** `gitpr-mcp` entry point via `pyproject.toml`
6. **Editor Extension 🆕:** independent VSIX package (`natanfiuza.gitpr`), with VS Code Marketplace and Open VSX channels; requires Node.js 20+ only for building, not for use
7. **Templates and languages OTA:** `templates/` and `langs/*.json` served from GitHub (main) — the `v0.0.35` bump renews the local copies in `~/.gitpr/langs/` when published; `__scripts_version__` **v0.0.4** renews the hooks
8. **Version derived from the code:** `pyproject.toml` uses `version = {attr = "src.updater.__version__"}` — `__version__` is the **only** source
9. **`package-data` matters:** the four embedded packs (`src/policy_packs/*`) travel in the wheel
10. **Release status 🆕:** **`v1.4.0` remains the latest tag** (2026-10-12). `__version__` is already at **1.4.1** (commit `46c25c1`, PR #217), but **the `v1.4.1` tag has not yet been created** and the `[1.4.1]` section of `CHANGELOG.md` is **in the working tree**, along with two untracked artifacts (`.gitpr/reports/pr_desc/develop_natan_20261018023014_PR_DESC.md` and `.gitpr/reports/release/develop_natan_20261018023153_RELEASE.md`). The release pipeline remains manual.
