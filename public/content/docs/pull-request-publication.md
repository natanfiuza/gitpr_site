# Technical Documentation: PR Publication to GitHub (`--publish`)

This documentation describes the Pull Request publishing flow via interactive terminal interface (TUI), allowing you to review, edit, and publish Pull Requests directly to GitHub without leaving the terminal.

---

## 1. What is the PR Publisher?

When you run the `gitpr --publish` command, GitPR generates the PR description with AI (same as the default command), saves the `.md` file locally, and opens an interactive panel directly in the terminal. This allows you to review, edit, and publish the Pull Request generated by the Artificial Intelligence before sending it to the remote repository via REST API.

---

## 2. Publishing Modes

The PR Publisher has **3 execution modes**, triggered according to the flags combined with `--publish`.

### 2.1 Interactive Mode — `gitpr --publish`

Opens the TUI for review and editing before publishing.

```bash
gitpr --publish
```

| Characteristic | Description |
|---|---|
| **Flow** | `git fetch` → AI generates PR → `.md` saved → TUI opens → user edits → POST to GitHub |
| **When to use** | When you want to review and adjust the PR content before publishing |
| **Result** | Pull Request created on GitHub with the edited content |
| **Ideal for** | Standard workflow — full control over what gets published |

> **Tip:** The local `.md` file is saved before the TUI opens and re-saved with any edits before publishing. You always have a backup.

---

### 2.2 Direct Publish — `gitpr --publish --no-edit`

Skips the interactive editor and publishes directly.

```bash
gitpr --publish --no-edit
```

| Characteristic | Description |
|---|---|
| **Flow** | `git fetch` → AI generates PR → `.md` saved → POST directly to GitHub |
| **When to use** | When you trust the AI output and want to publish immediately |
| **Result** | Pull Request created on GitHub without opening the TUI |
| **Ideal for** | CI/CD pipelines, quick fixes, automated workflows |

> **Caution:** Use with care — you will not have a chance to review or edit the content before publishing.

---

### 2.3 Auto-Publish Mode — `PR_AUTO_PUBLISH=true`

Configures GitPR to always open the publisher TUI after generating a PR description.

```bash
# In ~/.gitpr/.env
PR_AUTO_PUBLISH=true
```

| Characteristic | Description |
|---|---|
| **Activation** | Environment variable in `~/.gitpr/.env` |
| **Behavior** | Every `gitpr` execution opens the publisher TUI after generating the PR |
| **When to use** | When you always want to publish after generating the PR description |
| **Ideal for** | Teams that follow a "generate and publish" workflow |

---

## 3. Base Branch Configuration

The target branch for the Pull Request is resolved in the following priority order:

| Priority | Source | How to configure |
|---|---|---|
| **1 (highest)** | `--base` flag | `gitpr --publish --base develop` |
| **2** | `PR_DEFAULT_BASE` env | `PR_DEFAULT_BASE=develop` in `~/.gitpr/.env` |
| **3 (default)** | Auto-detection | `git symbolic-ref refs/remotes/origin/HEAD` (usually `main` or `master`) |

---

## 4. TUI Shortcuts and Navigation

The interface was designed to be fast and not require constant mouse use. You can navigate through fields using the `Tab` key and use the following shortcuts:

| Key | Action | Description |
|---|---|---|
| **`F1`** | Help | Opens a floating modal with quick interface usage instructions |
| **`F2`** | Save Local `.md` | Saves the updated content to the PR description file in the current project. Ideal when you want to refine the content later |
| **`F3`** | Publish PR | Connects to the GitHub REST API and creates the Pull Request in the remote repository. The direct link to the newly created PR will be displayed in the terminal |
| **`Esc`** | Exit | Aborts the operation and closes the interface without publishing |
| **`Tab`** | Navigate | Toggles focus between the interface fields |

## 5. GitHub Integration (PAT Token)

To create Pull Requests directly in the remote repository (`F3`), GitPR needs a **Personal Access Token (PAT)** from GitHub with `repo` scope.

### 5.1 Token Configuration

The first time you use `F3`, GitPR will:

1. Detect that no token is configured
2. Display the token generation URL with pre-filled parameters (`repo` scope)
3. Ask you to paste the generated token
4. Store it encrypted (Fernet) in the `~/.gitpr/.env` file

> **Note:** The Issue TUI (`gitpr -is`) shares the same token. If you already configured a token for Issues, it will be reused automatically.

### 5.2 Security

- The token is stored as an encrypted hash — never in plain text
- The master decryption key is located at `~/.gitpr/secret.key`
- The token is validated via `GET /user` before the TUI opens
- See the complete guide at [github-pat-integration.md](github-pat-integration.md)

---

## 6. GitHub API — PR Creation

The PR is created via `POST https://api.github.com/repos/{owner}/{repo}/pulls` with the following payload:

```json
{
  "title": "PR title (editable in TUI)",
  "body": "Full markdown PR description with commit message",
  "head": "Current branch (source)",
  "base": "Target branch (main, develop, etc.)"
}
```

---

## 7. Error Handling

| Error | Behavior |
|---|---|
| Invalid/expired token (401) | Prompts for a new token (up to 3 attempts) |
| Branch not found (422) | Shows GitHub's error message with details |
| No commits to merge (422) | Shows validation error suggesting to make changes first |
| PR already exists (422) | Shows the specific conflict |
| Network failure | Shows connection error message |
| Missing remote | Error before TUI opens — no API call attempted |

---

## 8. Environment Variables

| Variable | Default | Description |
|---|---|---|
| `GITHUB_TOKEN_ENCRYPTED` | *(none)* | Encrypted GitHub Personal Access Token |
| `PR_DEFAULT_BASE` | *(empty)* | Default target branch (uses auto-detection when empty) |
| `PR_AUTO_PUBLISH` | `false` | Set to `true` to always open the publisher after PR generation |

---

## 9. Practical Examples

### Example 1: Review and publish a feature

```bash
# You finished developing on the feature/login branch
gitpr --publish
# → AI generates the PR description and opens the TUI
# → Review the title, body, and base branch
# → Press F3 to create the PR on GitHub
```

### Example 2: Quick publish without editing

```bash
gitpr --publish --no-edit
# → PR is generated and published immediately
# → The PR URL is displayed in the terminal
```

### Example 3: Publish against a custom base branch

```bash
gitpr --publish --base staging
# → Target branch is set to "staging" instead of "main"
```
